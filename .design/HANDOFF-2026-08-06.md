## Process lessons — these cost real time

**1. Sharing one `CARGO_TARGET_DIR` across git worktrees is unsafe for CLI tests.**
They exec `target/debug/conway`, and concurrent workers building different source
trees clobber that single path — so a test can run against a sibling's binary. Two
workers independently hit and correctly diagnosed this; a third hit an analogous
collision on a shared scratchpad *output filename* and caught it only by noticing
its own tests were missing from the results. Library tests are unaffected. Give each
worktree its own target dir and each worker its own output path, or verify serially
at the end.

**2. A break-the-guard stub must break exactly the thing under test.** My first
attempt on the process-group test stubbed away *all* signalling, so the shell never
exited and the test failed on its own `invoke` timeout rather than on the assertion
being measured. The experiment did not run and it looked like it had.

**3. A stub paired with a workspace-wide run can leave the mutation in the tree.**
The 10-minute command timeout killed a run *before its restore step*. Caught only by
an explicit check afterwards. Scoped, fast verification only.

**4. Verify a coverage claim with a stub before asserting it.** I filed a finding
claiming a `strictest` regression "would pass every test in the workspace." Two stub
runs showed four pre-existing tests already caught it; the real gap was narrower.
Recorded as a correction against my own finding.

**5. Workers die.** One died on an API error after completing its work and before
committing; its output was recovered from the working tree and committed to protect
it, then verified independently rather than inheriting its claim. Check the tree
before assuming work is lost.

**6. `timeout` does not exist on macOS.** Two stub runs produced empty output while
appearing to have run.
