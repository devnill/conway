## What shipped this session

**Admission on the Backend port** (`92bfbd7`) — `Backend::admit`, the
`Admission` numbers, `BackendError::ContextTooLarge`, and one shared
`check_admission` both dialects call. Each adapter estimates from its own wire
body; no network call on the admission path, asserted by a wiremock
zero-request expectation. **Not yet consumed by any production path**, and
labelled as such at the declaration site.

**A latent defect fixed with it.** `BackendError::ContextTooLarge` was
`is_failover_worthy() == true` but had no arm in `conway-routing`'s `classify`,
so it fell through the catch-all to `Fatal`, whose `advances_chain()` is
false — core said "route past this candidate", routing said "give up".
`BackendError` is `#[non_exhaustive]`, so the missing arm compiled clean, and
the consistency test built to catch exactly this disagreement could not see it
because `all_variants()` was never extended when the variant was added. Now
classified `RequestIncompatible`, identical to its post-flight twin
`ContextOverflow`. **The guard was correct all along — it was blind, not
broken.** Adding the variant to `all_variants()` before fixing `classify`
reproduced the failure exactly (`fatal but failover-worthy`), which is the
P-15 evidence.

## Decisions recorded — do not silently revisit

- **`01KZF15KSWVD689HPBNNATFP8C`** — router identity lives on a
  `RouterFactory`, **not** on the `Router` trait. Selection must precede
  construction: the install path scans already-constructed values comparing
  ids, while `DeclarativeRouter::new` is fallible and needs backends that do
  not exist when `[plugins].install` is read.
- **`01KZF13BAR473X5SXN8HN95T6B`** — `BackendError::ContextTooLarge` is one
  candidate's refusal; `RoutingError::ContextTooLarge` is the whole request's
  refusal after all candidates refused. The router's window check is
  **advisory**; the engine's `admit` verdict is **authoritative**. They are no
  longer the same predicate and **are not expected to agree** — do not "fix"
  a disagreement by adding a test that asserts they match.
- **`01KZF1468YN9FGJHW3F2A6THM8`** — three corrections to the charter's own
  stated split: `failure.rs` goes to **core** (not the plugin), `config.rs` is
  **split**, `capability.rs` splits **three ways**.

## Two facts worth internalising before touching routing

**`Router` has exactly ONE method, `resolve`.** `state`/`record` belong to a
separate `HealthRegistry` port. The stateful half of routing is already behind
its own seam. An earlier reading of this page said otherwise and was wrong.

**The explain trap.** `with_router` sets `router_explain: None`;
`explain_routing` then returns an empty report; and `routes.rs` infers
"unknown role" from `entries.is_empty()`. A plugin-supplied router would make
**every** `conway routes explain` print "unknown role" for correctly-configured
roles. A silent behavioural inversion, not a compile error. Child C owns it.

## Process lessons — all of one family, all cost real time

**"The command appeared to run."** Three new instances this session, on top of
the two the previous draft recorded:

1. **Two concurrent `cargo test --workspace` runs were live at session start** —
   one stale from a previous session. Exactly the hazard the previous draft
   warned about, found running. Both killed; a single clean run was taken as
   the only evidence.
2. **`pgrep -f "cargo test"` matches your own wrapper shell**, because its
   command line contains that literal string. It reported "cargo already
   running" against nothing. Check for the actual binary
   (`ps -eo args | grep 'bin/cargo test'`), not the pattern.
3. **A monitor waiting for a process to disappear reports success when the
   process is *killed*.** An `until ! pgrep ...` loop fired "DONE" at 27 of 110
   suites. Three separate runs were truncated by task kills, and each left a
   partial log reading `failed=0`. **A truncated run looks exactly like a
   passing one.** Only `CARGO_EXIT` over a completed run counts.

**Subagents died three times** on API errors and a stall, each time after
producing nothing. The fix was narrowing each to two specs instead of five,
and authoring the last item directly. If an agent dies twice on the same task,
shrink its output before resuming it a third time.

**`record_decision` values are not markup-safe.** Three writes embedded literal
`<parameter>` tags in field values; two survived with substance intact, one
lost its entire rationale and had to be re-recorded as a supersede
(`01KZF121CA2Z10FFBCJ8SNSGBK` → `01KZF15KSWVD689HPBNNATFP8C`). **Read back
anything you record that matters** — `content_length` alone tells you whether
the body survived.

**Claim leases expire and `work_complete` correctly refuses the stale token.**
Re-claim, then complete. Size the lease to the work.
