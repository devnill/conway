## 3. Decisions taken this session (owner-confirmed)

### D-1. The membership test is refined; no code moves.

**Decision.** The last mile to an inference provider stays a swappable,
extendable unit outside the facade. Tools and the session store stay as honestly
named facade features.

**Reasoning.** `PHILOSOPHY.md`'s current test — *"does conway still function with
nothing at all filling this role? If no, something must ship"* — gives the wrong
answer for backends: it argues providers **must** ship. The better test is **"is
there a defensible universal default?"** JSONL-on-disk is one. A POSIX filesystem
is one. A provider is not. The thing with no universal default is exactly the
thing that must stay swappable.

**Already true in the tree:** `conway` depends on `conway-plugin-backends` not at
all; `conway-cli` attaches two dialects via `default_backends` — an opinion
shipped in the binary, opt-out.

**Consequences.** (a) Any "pull every adapter out of the facade" work is dropped.
(b) D1 remains, now solely because `jsonl-store` must become what its name says.
(c) **Stage 4 is promoted** — "swappable and extendable" is a stated value and is
only half true. (d) New item: amend `PHILOSOPHY.md`'s membership test per §7.

**Reopen if:** a genuinely provider-agnostic inference abstraction proves viable,
such that one universal default becomes defensible.

### D-2. Confinement uses general per-child narrowing, not a special case.

**Decision.** A parent may narrow **any** plugin's configuration for a child, with
semantics each plugin defines — `philosophy-debt.md` entry 3's shape 2.

**Consequence.** This is a **new core mechanism**, not a relocation. Confinement
was planned as a sub-task of a purity refactor; it is not, and must not ride
along inside one. Design it against **at least two consumers** — `conway.fs`'s
root and a plausible memory-plugin store scope — or it will be shaped by
`conway.fs` alone, which is the re-privileging this decision exists to prevent.

**Reopen if:** no second consumer materializes after the tier's next member
lands, making the general mechanism speculative generality.

## 4. Migration stages

Each ships green on its own. Stage 0 gates everything; 3 and 4 are independent of
1/1.5/2 and may run in parallel.

**Stage 0 — Preconditions (~3 days).** Not hygiene; this is what makes the
migration safe. (a) `cargo fmt --all` as one isolated commit, then gate — without
it every refactor diff is unreadable; this is the sequencing `ci.yml:11-15` itself
prescribes. (b) Fix the false invariants so docs can check your work; two of them
(T2, T6) dissolve in later stages rather than needing a doc edit — resolve those
against the tree. (c) Ship the `GP-*`/`P-*` dictionary: **748 citations in
production source resolve to nothing**, plus 391 board ULIDs. (d) Stand the §2
invariants up as CI guards pinned at today's values — this ratchet is what turns
"we moved it" into "it can't move back." (e) Add `cargo-deny`, `cargo doc -D
warnings`, MSRV. (f) Same edit class: `README.md:20-24` headlines circuit breakers
a default build lacks, and `docs/getting-started.md` teaches `models.json` as
mandatory while quoting an error that exists at exactly one place in the tree —
`conway-plugin-routing/src/router.rs:257` — so it cannot occur without the plugin.

**Stage 1 — Contract crate purity (~1 week).** 1a: cut `runtime → session`, move
`TranscriptResolver` + `provenance` helpers to core, turn on T4. 1b: extract
`conway-testkit`, turn on T3.

**Stage 1.5 — Narrowing, then confinement (~2 weeks, design first).** 1.5a: design
and land the narrowing port against two consumers. 1.5b: move confinement into
`conway.fs`; turn on T2; clears ledger entry 3. 1.5c: retire `PathArgs`, the
broker's pre-gate root check, and `SubagentSpec::root`; decide whether
`--root`/`with_root` become `conway.fs` config or go away. **Guard against the
inversion** — entry 3's own warning: if `conway.fs`'s root ends up harder to reach
than `--root` is today, the argument stops being honest.

**Stage 2 — Facade becomes a facade (~1 week, sliced).** Permission-file I/O →
`conway/src/permissions/`; `intent.rs` → runtime; `pull_in`/`promote`/`purge` →
runtime beside `AgentTree`; `TuiSection`/`ThemeConfig` → `conway-cli` and the
"4× the TUI's 15s heartbeat" constant becomes caller-supplied (T7); resolve D9 the
tree's way (T6).

**Stage 3 — Assembly as a facade capability (~2 days, independent).**
`ConwayBuilder::install_selected(plugins, router_factories, backend_factories)`
over **caller-supplied** bundles, so the facade still depends on no plugin crate.
`conway-cli`'s `install()` collapses to three `vec![]`s and a call;
`docs/embedding.md:285` stops showing embedders a hand-rolled
`if wanted.iter().any(...)`. Satisfies T8 in practice.

**Stage 4 — Provider variants, one mechanism (~1 week, independent, promoted by
D-1).** 4a: Anthropic kind reads `ctx.extra` and validates its own keys
(`anthropic_version`, headers) — the port field exists and its own doc notes
*"neither shipped kind reads it."* 4b: lift the profile machinery to a
kind-agnostic facility — **not a second `ProfileStore`**; §5 applies before the
duplication exists. 4c: Anthropic profile set; one documented procedure for both
wire families.

**Stage 5 — Internal shape (opportunistic).** `Conway` after Stage 2; `run_inner`
(543 lines, depth 12, eight early-return exits, `report_slot` set twice) as a
`TurnPhase` state machine; the TUI's three registries collapsed to a
parser-generated one (D8/T9). **Exception:** the allow/deny/prompt path copied
4–5× and the duplicated root canonicalization are `CONTRIBUTING.md` §5 and are
**mandatory, ungated by §4** — each names a failure mode CI structurally cannot
catch. Move them earlier whenever those files are open.

**Stage 6 — Fill the tier.** Hooks rung first (design complete; the ledger notes
today's seams *"require Rust and a rebuild, which is exactly the cost the hooks
rung claims to remove"*), then compaction, memory, skills, MCP. Stage 3 makes each
install identically across every host.

## 5. Do not re-litigate these — they were checked and found fine

Corrections made during the review, recorded so the next reader does not redo
them:

- **`intent.rs` is not a baked-in opinion.** It routes under a *declarative*
  `intent` role; `config.roles` defaults empty; with no `[roles.intent]` entry
  classification **degrades rather than running** (`intent.rs:237`). Only its
  placement in the facade is arguable, and that is craft.
- **`MinimalRouter` in `conway-core` is sanctioned**, explicitly, by PHILOSOPHY §5
  "Routing": *"the core keeps the smallest thing that has to be true: a role names
  a model."* Do not move it.
- **`HealthProber` needs no action.** 675 lines that never run — but §4 records it
  as having *failed the repair test* (probing shaves a failed round trip: latency,
  not correctness), and `probe_enabled` correctly defaults false. Priced and
  stated; a working state.
- **`.design/extension-architecture.md`'s 3,199 unbuilt lines are not a defect.**
  §2: *"Inertness is not the defect."* The directory is declared non-authoritative
  and the document is labeled "design, not implemented."
- **Routing not being built in is correct and costs less than the docs imply.**
  `AttemptEngine::execute` (`attempt.rs:239`) walks the whole candidate list
  regardless of router, and `Backend::admit` skips a candidate that cannot take
  the request. **Ordered fallback works in a default build.** The plugin adds
  pre-flight capability filtering and breakers.
- **Rewriting `CHANGELOG.md` is out.** Rewriting released sections destroys a
  record §7 protects, and verbosity is not falsehood. Only the Keep-a-Changelog
  header claiming an unhonored format is a §2 defect — resolve `[Unreleased]`-forward.
- **No comment-density target.** §4: an unmeasurable proxy is an argument against
  shipping. Use the stale-invariant count (4 today) as the metric instead.
