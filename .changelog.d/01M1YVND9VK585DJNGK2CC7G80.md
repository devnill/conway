### Changed

- **`conway.idiom` now finds an operator's own project instructions by walking up to the enclosing git repository root, and falls back to `AGENTS.md`** — board item `01M1YVND9VK585DJNGK2CC7G80`. Project-scope resolution used to be a single direct `<cwd>/.conway/instructions.md` join, never walking above `cwd`: launching from a subdirectory of an already-`.conway`-configured repository (a package inside a monorepo, `docs/`, a nested crate) silently saw no project instructions at all, even though one existed at the repository root. `conway_plugin_idiom::project_instructions_path` now walks from `cwd` up through each ancestor directory, nearest first, taking the first `.conway/instructions.md` it finds, and stops at the enclosing git repository root (the nearest ancestor, including `cwd` itself, containing a `.git` entry) rather than continuing to the filesystem root; with no enclosing git repository, the walk is `cwd` alone, exactly the prior behavior. When that walk finds no `.conway/instructions.md` anywhere, it tries the identical directory list again for `AGENTS.md` — the standing-instructions filename several other harnesses already converge on — before giving up: an operator arriving from one of those tools is read without re-authoring anything. `.conway/instructions.md` wins whenever both exist anywhere on the walk, even one nearer to `cwd` than a farther `.conway/instructions.md` that wins, since conway's own file is the more specific declaration; both land under the same `conway.idiom.operator.project` fragment, distinguished only by `Provenance::Operator`'s own `path`, so `/context` and a session's durable log already name the exact file read with no new field. `CLAUDE.md` is deliberately not read (ruled single-vendor); global scope (`<home>/.conway/instructions.md`) and the missing-is-silent/unreadable-is-loud policy are both unchanged. `docs/plugins/idiom.md`'s "Location" section and `docs/getting-started.md` are updated to match.
