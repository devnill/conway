### Fixed

- **A model that stringifies a nested-object tool argument (e.g. `conway_spawn`'s `budget` sent as `"{\"max_steps\": 5}"` instead of the object itself) no longer ends the whole session with a misleading `fatal error: ... no candidate` — board item `01M23SDCE6T85Z48CRQ8NBY6PV`.** `SchemaValidator` (`conway-plugin-backends`) now coerces an unambiguously stringified OBJECT or `null` argument — a string that parses as JSON, whose parsed shape is an object or `null`, and that then validates against the exact schema branch that rejected the string — before ever reporting a parse failure; a stringified number, boolean, or array is deliberately never coerced even when it too would parse and then validate. Each firing is logged and, on a streaming backend, recorded as a new durable `Event::ToolArgumentCoerced` naming the tool and the argument's JSON Pointer path, so it is countable in an ordinary run rather than only under `--verbose`/`RUST_LOG`. A malformation coercion can't resolve is handed back to the model as a real corrective `ToolResult` (naming the tool, the argument path, and what was wrong) appended to the one retry `AttemptEngine` (`conway-runtime`) grants — not a blind resend of an identical request. Only once that retry is also exhausted does `AttemptEngine` surface a typed `RuntimeError::ToolCallRejected`, naming the tool and the argument and carrying every candidate the chain tried (not only the last), instead of collapsing into `RoutingError::NoCandidate`'s "no candidate" wording, which was actively wrong (a candidate answered, with a malformed call, not silence).

### Changed

- **`docs/agents.md`** now documents the three-step policy a malformed model-invoked tool call goes through: coercion (durably logged, narrowed to object/`null` shapes), a bounded model-facing retry carrying the actual correction, then a typed refusal naming the tool and argument.
