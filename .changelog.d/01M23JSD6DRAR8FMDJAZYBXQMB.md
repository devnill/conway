### Fixed

- **A `report` call whose `summary` is still too long after its one corrective retry is truncated and delivered — marked as truncated — instead of destroying a completed piece of work — board item `01M23JSD6DRAR8FMDJAZYBXQMB`.** `report`'s `summary` has a 2,000-character `maxLength` for a good reason (an unbounded summary would blow the parent's context), but a model that writes past it used to lose everything: no truncation, no second chance, no partial hand-back. `AttemptEngine` (`conway-runtime`) now gives an oversized `summary` that survives board item `01M23SDCE6T85Z48CRQ8NBY6PV`'s bounded corrective retry one more, entirely local fallback: the summary is truncated (on a Unicode-character boundary, never a raw byte offset) to the exact bound `report`'s own schema declares, with a marker appended naming the original length and the bound exceeded, and delivered as an ordinary successful `report` call. The marker is visible to both the operator and the parent MODEL — it lands directly in the terminal `AgentResult.summary` a parent's own context is built from. A summary already within the bound is never touched or marked. This fallback is scoped to exactly this one field on this one (side-effect-free) tool; every other schema failure — on `report` or any other tool — still reaches the existing typed `RuntimeError::ToolCallRejected` refusal, naming the tool and the argument, never a misleading "no candidate"/routing failure.

### Changed

- **`docs/agents.md`** documents the one exception to its existing three-step malformed-tool-call policy: `report`'s own `summary`, truncated and marked rather than refused once its corrective retry is also exhausted.
