### Fixed

- **The session-scoped shell-prefix grant's compound-command exclusion (added above by board item `01M32EBPWZZG6EA77ZG5KYC8KQ`) could be bypassed with a single embedded control character — CRITICAL, closed before anything in this release should be trusted** — board item `01M38MDGCNVF2GE3JEQTRXSN2S`. The exclusion's compound scan and its prefix match both run against `AuthorizedCall::rendered`, but by the time the broker sees that field it has already passed through `conway_runtime::tools::runner`'s control-character sanitizer, which rewrites a real embedded newline or carriage return (among the scan's own named constructs) into a single, space-flanked placeholder — invisible to a literal `\n`/`\r` check, and its own token to a whitespace-delimited prefix match, so `git status \n rm -rf /` sanitized to `git status <placeholder> rm -rf /` matched a `git status` grant's first two tokens cleanly while `BashTool::invoke` went on to run the ORIGINAL, unsanitized, still-newline-intact command for real — the exact "allow one command, get any command" failure the exclusion exists to prevent. Every test guarding this path before this item built its `AuthorizedCall` fixture by hand, setting `rendered` to a literal string that bypassed the sanitizer entirely, so nothing exercised the seam that actually launders the evidence in production. `PermissionBroker::shell_prefix_grant_allows` now also refuses any candidate `rendered_evidence_is_untrustworthy` flags (a raw control character or the sanitizer's own placeholder) — the identical fail-toward-restriction check `PatternRule::matches_deny` already applies on the deny side, reused rather than restated — before the compound scan and prefix match ever run. `docs/permissions.md`'s "Limits" section and this changelog's own entry above are corrected to state this precisely rather than the narrower, now-accurate-only-after-this-fix claim they shipped with. See `crates/conway/tests/shell_prefix_grant_newline_seam.rs` for the real-`bash`-tool, real-render-seam regression proof.
