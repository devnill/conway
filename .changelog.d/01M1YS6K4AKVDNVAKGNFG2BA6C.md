### Fixed

- **`docs/plugins/statusline.md`'s worked example used a config key the settings schema had already moved away from** (`[plugins].statusline` instead of `[tui.status_line_command]`), and its "eleven shipped first-party plugins" figure was stale (now twelve, `conway.confine` included). The example is now mechanically guarded: `crates/conway-cli/src/tui/config.rs`'s `the_statusline_doc_example_loads_through_the_real_tui_schema` extracts the doc's own fenced JSON block and deserializes it through the real `TuiSection` schema, so a future edit that reintroduces the wrong key or any other rejected field fails the test, not just a reader's copy-paste.
- **Two load-bearing tests close a verification gap in `conway.statusline`'s live-refresh behavior**: `two_refresh_ticks_with_a_changing_contribution_change_the_rendered_line` (`conway-cli`) proves the rendered status line changes between two consecutive polls of a genuinely-changing contribution (a single empty-to-populated tick cannot distinguish a working refresh from none at all); `a_command_that_times_out_leaves_the_previous_good_value_visible_while_in_flight` (`conway-plugin-statusline`) proves a command sleeping past its own `timeout_ms` leaves the prior successful value visible and the read path non-blocking while that run is still in flight.
