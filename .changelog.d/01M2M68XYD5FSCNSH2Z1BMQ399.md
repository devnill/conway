### Fixed

- **Guided setup's context window now survives a change of directory** — board item `01M2M68XYD5FSCNSH2Z1BMQ399`. `settings.json` and `models.json` used to land in different places: `settings.json` went to the resolved config layer (`$CONWAY_CONFIG_DIR`, `~/.conway/`, or a `--config` target), but the model's context window went to `<the directory conway happened to be invoked from>/.conway/models.json` — a path with no relationship to where `settings.json` landed. Measured consequence: guided setup recorded a real 1,048,576-token window, and `conway routes explain default` reported `headroom_tokens=104857` in that one directory and `8192` — the assumed dialect floor — from anywhere else. That 8,192 is the same admission bound that lost a real session on 2026-09-09. Guided setup now writes `models.json` beside the `settings.json` it just wrote **and** persists an absolute `[models].metadata_path` pointing at it, so the window resolves identically from any working directory. Writing the file beside `settings.json` alone was not enough: `[models].metadata_path` defaults to the relative `.conway/models.json`, which `config::merge` resolves against the *reading* process's current directory, so the relocated file was one nothing looked for. A pre-existing project-scope `models.json` is left untouched — precedence (project outranks user) is unaffected, and existing files are never migrated.

### Added

- **`conway::config::set_metadata_path`** writes `[models].metadata_path` into a settings file, creating the `models` object and the member when either is missing. It is the eighth writable field to go through `config::writer`'s shared `find_or_create_path` primitive (board item `01M250DEEWA6FJZE11PKCAYNDC`), and is correspondingly short: it supplies a path and a value shape, and nothing else.
