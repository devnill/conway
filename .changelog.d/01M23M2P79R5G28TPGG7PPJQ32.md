### Fixed

- **Adding a model no longer commits conway's own guess about its context window without saying so** — board item `01M23M2P79R5G28TPGG7PPJQ32`. Guided setup and `/settings` → providers → add used to have three branches with three different disclosure levels: a successful probe persisted immediately, an already-verified dialect baseline resolved and returned in total silence, and only the one branch with nothing to offer ever asked the operator anything — and even that branch never named the specific number (`32768`) it would silently assume if declined. Investigating this against `ollama_cloud` (the provider that motivated this item) found discovery can never succeed there at all: its `/v1/models` listing carries no `context_length`/`max_model_len` field for any model, and its hosted origin does not answer Ollama's native `POST /api/show` either — so every Ollama Cloud add reached the one branch that, before this fix, still resolved silently past the operator. Every branch now confirms what conway resolved — its value and its provenance (`probed`, `verified`, or `floor (assumed)`, naming the exact number) — before it governs, in an interactive context; a non-interactive run is unchanged.

### Changed

- **Accepting a resolved context window default no longer freezes it as a permanent override.** A `models.json` entry is the only persisted channel this codebase has for a per-model window, and writing one always outranks a later probe. Accepting a probed value or an already-verified dialect baseline (a bare `Enter` in guided setup; an immediate confirm notice in `/settings` → providers) now writes nothing at all, so a later, better probe can still improve it; typing a different number still persists it, unconditionally, as an override that no later probe may silently replace. `docs/providers.md`'s "Establishing the window at setup" and `docs/getting-started.md` state the full rule.

### Added

- **`App::apply_edit_model_context_window`** (`crates/conway-cli/src/tui/app/provider_manage.rs`) — the write-side primitive for changing an already-configured model's context window without hand-editing `models.json`, reusing the same persist path a freshly-typed add-time answer already uses. Its own UI entry point (a selectable, editable row in the providers list) is a disclosed gap of this item, not yet wired: the providers list's rendering and keybindings live outside this change's own scope.
