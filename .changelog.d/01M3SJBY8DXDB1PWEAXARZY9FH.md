### Fixed

- **A resumed session's last turn no longer sits there silently if it never got a reply** — board item `01M3SJBY8DXDB1PWEAXARZY9FH`. Quitting, killing, or losing the process mid-turn now shows a plain "this turn was interrupted; it never got a reply" notice the next time that session is resumed or forked from, whether the turn was cleanly aborted (`Ctrl-C`/quit) or the process never got the chance to record anything at all after the prompt.
- **A resumed transcript no longer shows internal bookkeeping the live session never showed** — the same item. Replaying a session used to sprinkle in `[permission_decision record not shown in the transcript]`-style placeholders and `context report: N segments, M tokens` lines for record kinds the live TUI never renders a line for at all; the replay (and `/export`'s Markdown rendering, which reads the same mapping) now matches what the live transcript actually showed. A persisted `!>` shell command (previously swept into the same placeholder) now replays as a real shell entry instead.
- **Resuming a session continues on the role it was actually using, not silently your current default** — the same item. `--continue`, `--resume <id>`, and the TUI's `/resume` all read a session's own recorded role back correctly; if that role was since renamed or removed from config, resuming now falls back to the current default role instead of failing the turn outright, and records a notice naming both the stale role and the fallback on the resumed transcript.
- **A resumed transcript now shows a denied/aborted tool call's own "why", not just its silent absence** — the same item, closing a gap the fix above left: a session resumed after an operator answered a permission prompt live (allow/deny, with or without feedback) now replays that exact dim "allowed once · waited …"/"denied: …" note, and a tool call whose turn was aborted mid-wait (the one denial with no tool-result record of its own to fall back on) now replays the plain "tool call … denied" notice — both exactly as the live session showed them. Every other auto-resolved decision (a matching rule, a cached grant, plan mode, a hook) still replays silently, matching what the live session showed for those too.
- **A session's role fallback (above) is now durable, not re-announced on every resume** — the same item. The first resume that falls back to the default role now also writes that fallback onto the session's own header, so the SAME session's next resume reads back an already-current role and skips the fallback (and its notice) entirely, instead of re-deriving and re-recording it every time.

### Changed

- **`docs/sessions.md`** gained "Role and model continuity" and "A turn that never got a reply" under Resuming, describing the fixes above, including that the role fallback is now written back durably so it only happens, and is announced, once per session.
