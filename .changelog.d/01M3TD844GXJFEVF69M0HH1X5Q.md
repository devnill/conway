### Added

- **In `Prompt` mode, a `read`/`grep`/`glob` call whose path resolves inside your project no longer prompts** — board item `01M3TD844GXJFEVF69M0HH1X5Q` (RULING 2026-09-30). Previously every distinct tool call paused for a decision, including the very first in-project read of a brand-new session — the dogfooding finding that trains operators to stop reading prompts. Now a `Read`/`Search`-category call whose declared path argument (resolved the identical way a `paths_under` permission rule already resolves one — never the sanitized display text) resolves inside the project is allowed without ever reaching the gate; "the project" is `--root` when set, or, absent one, the git root enclosing the session's launch directory (the same boundary conway already keys session storage on), falling back to that directory itself outside any repository. A `..`/symlink/absolute escape, or a read-category call declaring no path argument at all (e.g. `web_fetch`), still prompts exactly as before, and every operator `deny`/`prompt` rule still outranks this default unconditionally. `Plan` and `AutoAllow` modes, and every edit/delete/move/execute/fetch call, are unaffected. See `docs/permissions.md`'s "The default: in-project reads don't ask" for the full contract and a worked "tightening it" example.
