### Fixed

- **Plain `conway -p` (the default `text` output format) no longer silently drops the runway warning, the budget-crossing notice, or the `max_tokens` silent-turn notice** — board item `01M2MGPF52NHFYN1AKBPR9FDK6`. `TextRenderer::on_event`'s wildcard arm caught `Event::AgentProgress` and `Event::BudgetWarning` along with everything else it didn't name explicitly, so every notice conway emits through those two events (including the just-landed `max_tokens_silent`/`max_tokens_truncated` wording, board item `01M23JRDAM480SRXFGM46GBVA6`) produced zero output for a one-shot script watching stderr — the exact "silence is indistinguishable from a hang, a crash, or a bug" gap that item closed for the TUI, still open for the one surface with no human watching a transcript scroll by. Both events now render to stderr as a `conway: warning: …` line, unconditionally (never gated behind `--verbose`); stdout is untouched either way, so `--output-format json`'s one-document contract stays exactly as clean as before.

- **`--output-format json` shows progress and runway notices on stderr too** — board item `01M2MGPF52NHFYN1AKBPR9FDK6`. `JsonRenderer` dropped every streaming envelope, so a `json`-mode caller saw no runway warning, no budget-crossing notice, and no "the turn produced nothing" note. It now writes those two to stderr as prose, exactly as `text` mode does. Stdout is untouched and still carries exactly one JSON object: the notices go through `diag::warn`, which writes to the process's own stderr and has no path to the renderer's stdout handle at all.
