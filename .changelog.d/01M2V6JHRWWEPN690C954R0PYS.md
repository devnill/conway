### Fixed

- **Launching conway from a subdirectory of a repository now finds the repository root's `AGENTS.md` and `.conway/instructions.md`, and the model is told a real working directory instead of `.`** — board item `01M2V6JHRWWEPN690C954R0PYS`. `ConwayConfig::cwd`'s wire default is the literal relative `"."`, and nothing ever replaced it with `LoadOptions::cwd`'s real `std::env::current_dir()`, so every consumer doing path arithmetic on it was working from a placeholder. `conway.idiom`'s documented walk up to the enclosing git root was the visible casualty: on `"."` the walk is inert (`Path::new(".").parent()` is `Some("")`, whose own `.parent()` is `None` — two relative misses and it gives up), so a launch from `pkg/sub/` silently saw no operator instructions at all, with no error and no warning; from the repository root it only ever appeared to work because `.` itself held the file. The second symptom was the environment block, which told the model `Environment: cwd .; ...` — a plausible-looking value it could reason from. `config::load` now resolves `cwd` once, against the load's own invocation directory, before any consumer sees it: an absolute value is returned exactly as written, a relative one is joined onto the invocation directory and lexically normalized. Fixed at the input rather than inside the walk deliberately — canonicalizing at that one leaf would have left every other `cwd` consumer reading `"."` and would not have touched the environment block at all. The wire default stays `"."` so `default_document` and `ConwayConfig::baseline()` cannot drift; only what `load` hands back changes. A config built by hand through `ConwayBuilder::from_parts`/`from_config`, which bypasses `load` entirely, still carries whatever `cwd` its author set — now stated on the field itself.
- **A session now records the directory it actually ran in, and the session picker's project label is no longer blank** — same board item, same root cause. `Conway::new_session` defers an unset `SessionSpec::cwd` to `ConwayConfig::cwd`, so every session created by a normally-launched conway stamped `.` into its own `SessionMeta`; and `ConwayBuilder::build` derives the discovery project key from that same field, so the `project:` label the picker shows on a current-project match encoded to the empty string. Both now carry the real directory. (The picker's label is derived from the exact launch directory while the session store's own root is keyed off the enclosing git repository, so the two spellings can still differ for a subdirectory launch — a pre-existing divergence this change does not close, only makes visible.)
