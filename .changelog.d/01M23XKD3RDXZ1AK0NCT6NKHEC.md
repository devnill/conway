### Fixed

- **`.gitignore` no longer un-ignores a project `.conway/settings.json` — board item `01M23XKD3RDXZ1AK0NCT6NKHEC`.** The `.conway/` allowlist re-admitted `settings.json` on the (never-true) premise that it was deliberately-shared team configuration; the file was never actually tracked, and it can hold a literal API key inline (`BackendEntry.api_key`) alongside machine-specific `backends`/`roles` tables. A `settings.json` written in a working tree is now ignored by git, matching every other newly-invented file under `.conway/`. `.conway/permissions.json` and `.conway/instructions.md` stay tracked, and so does `.conway/agents/`, checked against the same rule and kept: agent definitions are project-shared persona markdown with a schema (`name`, `role`, `tools`, `model`, `max_steps`, `result_contract`, `skills`) that cannot carry a credential. `CONTRIBUTING.md` now tells a contributor where their own settings belong (`~/.conway/settings.json`, which a project `settings.json` still outranks locally without being shared).
