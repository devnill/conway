### Fixed

- **`conway --fork-from <ref> --model <m>` now actually routes the forked child to `<m>`** — board item `01M2MNP9H9Q52W84X3QMBC3PKM`. `--model` was accepted alongside `--fork-from` and silently dropped: the TUI's `fork_from_ref` never parsed it and never called `ForkSpec::model`, so a forked child always routed to whatever its role chain resolved to, with no error and no notice. `fork_from_ref` now parses `--model` the same way every sibling arm does (`crate::model_pin::parse_model_pin`, matching `--resume`'s own contract exactly), so a malformed value is a usage error at launch rather than a silent no-op, and a well-formed one reaches `ForkSpec::model` and routes the child's first turn accordingly. `--cwd`/`--agent` stay refused on this arm (session-identity choices a fork always inherits from its parent); `--model` is deliberately not refused alongside them — it is a routing choice, not an identity one, the same reasoning that already lets `--resume` accept it.
