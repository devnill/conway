### Fixed

- **`/conway.skills.propose` gave no sign it was running.** The status line kept reading plain `idle` for the whole run of its ephemeral fork; it now shows a spinner and `proposing a skill…`, mirroring `/ask`'s own in-flight indicator.
- **`/help` did not list the skill-proposal modal's keys (`Enter` write / `e` edit / `Esc` discard) or `/distill`'s modal's (`Enter` / `e` / `Esc`).** Both are now in the "modal keys" group alongside the `/ask` modal's and the intent-confirm card's.
- **A multi-line bash command rendered in the permission prompt as a single line with `�` standing in for every lost line break.** `req.rendered` reaches the TUI already sanitized (every control character, newlines included, already replaced by the placeholder), so the prompt's command block now recovers the raw, unsanitized command text from the call's own arguments and splits it on its real line breaks before sanitizing each line independently — real line breaks stay real, and every other control character is still neutralized exactly as before.
- **`conway --help` and several subcommands' `--help` printed board item ids and internal module references** (e.g. `--default-permission-mode` citing `conway::config::schema::PermissionsConfig::default_mode`, `memory`/`plugin`/`trust`/`doctor` citing their own module docs) picked up from clap deriving help text straight from rustdoc doc comments. Each affected flag/subcommand now carries an explicit, short operator-facing `help`/`long_help`/`about`/`long_about` clap attribute instead; the rustdoc itself is unchanged.
