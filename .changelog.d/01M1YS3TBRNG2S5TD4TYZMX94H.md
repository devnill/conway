### Added

- **`conway.checkpoint`: roll back the model's own file changes** — board item `01M1YS3TBRNG2S5TD4TYZMX94H`. A new first-party plugin, `crates/conway-plugin-checkpoint`, in the default opinion set: snapshots a file's bytes around every `write`/`edit` tool call into a shadow store under `.conway/checkpoints`, and `/conway.checkpoint.list`/`.diff <seq>`/`.rollback <seq> [<path>] [--all] [--rewind]` to preview and undo them. A rollback preserves an operator's own hand edit by default — a three-way check against the snapshot, conway's own last recorded write, and the current bytes reports a conflict per file rather than silently overwriting, forceable with `--all` — and snapshots the current state first, so a rollback is itself listed and undoable. `--rewind` composes with `conway.history`, restoring files and forking the conversation at the same sequence in one command. Two bounds, both with a visible notice on skip/eviction: 2 MiB per snapshotted file, 256 MiB total per project. Does not capture a change made through `bash` — only `write`/`edit` are observed — documented plainly in the plugin's own description and `docs/plugins/checkpoint.md`. This reverses `docs/vision/CATALOGUE.md`'s prior "explicitly not recommended" ruling on filesystem checkpointing, which that page now records alongside the reversal's own cost.
