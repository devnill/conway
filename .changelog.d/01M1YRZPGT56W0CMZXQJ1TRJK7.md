### Added

- **A fallback now names WHY, with numbers — `route_reason.after` (`RoutingReason::Fallback`) is populated instead of always empty** — board item A1d, "say why a turn fell back". `DeclarativeRouter::evaluate` now records every earlier-in-chain candidate it pre-filtered (capability floor, headroom, breaker open) on the fallback that survives past it, and `AttemptEngine::execute` additionally names any `Backend::admit` refusal discovered after routing — both reusing the router's existing reason vocabulary (`RoutingReason`/`AttemptFailure`), never a second one. `conway routes explain`'s pre-existing `fallback #N after: <model>: <reason>` rendering (already wired, previously always empty) now shows real content. The TUI shows a one-line dim notice on the turn (`routed to X — Y skipped: <reason>`) reusing the existing `Entry::Notice` rendering, and `/why` now keeps a short bounded session history of routing decisions (`AppState::model_decision_history`, replacing the old single last/previous pair) instead of only the latest one. `route_reason`'s wire shape is unchanged — `after` gains content, not a new field — so an existing consumer parsing today's records is unaffected.
- **`/model`/`/role` switch-forks no longer pile up in `/agents`** — the same board item, its "switch-forks do not pile up" half. Option (a): a chain of `/model`/`/role` switches now collapses to ONE visible row (its live tip) in the `/agents` panel, via a new `AppState::switch_lineage` side-table and `AppState::switch_history` for full recoverability — every underlying fork is still a real, independently-logged agent; only the panel's draw-time projection collapses, so nothing about the per-turn log semantics changes.

### Fixed

- **`docs/routing.md`'s worked fallback examples updated to show a populated `after` field**, matching the behavior change above rather than the previously-always-empty placeholder they used to show.
