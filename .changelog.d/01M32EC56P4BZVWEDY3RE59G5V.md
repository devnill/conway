### Fixed

- **Editing an existing file through the `write` tool (or its confined-path counterpart) no longer strips its unix mode — a script keeps its executable bit, a keyfile keeps its `0600`** — board item `01M32EC56P4BZVWEDY3RE59G5V`, hit directly during a recent proxy run when editing a shell script silently broke it. The atomic write-temp-then-rename protocol used to leave the replacement at the temp file's own umask-derived mode, discarding whatever the destination already had; `copy_existing_mode` (`crates/conway-tools/src/fs/write.rs`) now copies the existing file's mode onto the temp file before the rename whenever the destination already exists, and `copy_existing_mode_confined` (`crates/conway-tools/src/fs/beneath.rs`) does the same through `cap_std`'s `Dir::set_permissions` for the confined write path. A not-yet-existing destination is unaffected — it still gets the temp file's umask-derived mode, as before. A mode-copy failure degrades to a tracing warning rather than failing the write.
