### Fixed

- **`describe_tool` (`conway.toolindex`) no longer prompts for permission, in any permission mode** — board item `01M3TEK20AERQNZRVY7G5F50VJ` (RULING `01M4654R10FGT9Y0FPNBN5DKPF`). DOGFOOD 3 found that with `conway.toolindex` installed, the model's first use of each deferred tool was preceded by a permission prompt for `describe_tool` — a lookup of a schema conway's own process already holds, touching nothing — and pressing `a` ("always") did not help, because `a` grants only that exact call's exact arguments, and `describe_tool`'s `name` argument differs on every call. The permission broker now carries a small, FIXED, first-party allowlist of harness-introspection tool names (today: exactly `describe_tool`) that it exempts from every prompt, in every permission mode — a broker-owned decision, never a tool-declared property (a `PermissionClass::Safe` declaration alone does not exempt a call; the broker does not consult that field for this decision, so a third-party plugin cannot self-declare its way out of a prompt). Matched by tool name only — a disclosed gap, since `AuthorizedCall` carries no plugin-id field. Every operator `deny`/`prompt` rule still overrides the allowlist, in every mode, exactly as it overrides the existing in-project-read default. See `docs/permissions.md`'s new "Harness-introspection tools never prompt" section.
- **The permission prompt's footer now states what `[a]` ("always") actually grants, instead of implying it is broader.** `[a]` has always matched a later call only when its arguments are byte-identical to this one (`PermissionBroker`'s `CacheKey` hashes the full call, not just the tool name) — but the footer's own confirm screen (after the first `[a]` press arms it, board item `01M44PK089DF2M9TM3C4P5CKMZ`) used to say "would allow EVERY future call like this," which overstated the match. Both the ordinary footer and the confirm screen now name the real scope: "exact args" for a structured tool, "exact command" for a shell call. `docs/permissions.md`'s prompt diagram and `a` row are updated to match.
