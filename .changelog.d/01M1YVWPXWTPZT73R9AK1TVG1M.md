### Added

- **`conway -p --input-format jsonl`: a persistent, stdin-driven one-shot session.** Instead of reading one prompt and exiting, conway now keeps the process open and reads newline-delimited JSON from stdin, one input per turn or operator action: `{"type":"prompt","text":...}` runs a turn on the root, `"steer"`/`"cancel"`/`"await"` map to the matching session operator actions, and `{"type":"end"}` or EOF ends the session with its documented exit code. Requires `--output-format jsonl`; a malformed line yields a driver `{"type":"error",...}` line on stdout and never stops the driver. A `"prompt"` sent while a turn is already running is queued, not rejected, and `seq` keeps climbing across turns in the same process. See `docs/scripting.md`'s "Driving conway as a persistent process" section for the full protocol and a worked Python example.

### Fixed

- **A stdin read error (e.g. invalid UTF-8) on a driven `--input-format jsonl` session no longer hangs the process forever** — same board item. A read error set the internal "stdin is done" flag but skipped the immediate end-of-run check EOF's own arm already ran, so the driver kept waiting for a turn result that could never arrive once nothing could ever produce one. It now behaves exactly like EOF: reported as a driver `error` line, then the documented exit code for "no turn ever ran."
- **Input written after an explicit `{"type":"end"}` is now rejected instead of running another turn** — same board item. A driver that kept its pipe open past its own `"end"` line (deliberately or not) could still queue and run a further `"prompt"`; any line read after `"end"` is now answered with `{"type":"error","message":"input after end"}` and never run, while a prompt already queued BEFORE `"end"` still drains normally. See `docs/scripting.md`'s driver protocol section.
