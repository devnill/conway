### Fixed

- **The status bar's elapsed counter now shows how long the running tool call has actually been going, instead of a literal `0s`** — board item `01M2VDD6MQG7H73AHGX8HJGV2J`, the sibling of `01M2V60KWK9AYX3J7V5TPJZN7Q` and the same root cause one rung over. `running bash… 0s` read its figure from `turn_started_at`, which means "a model turn is in flight"; the agent loop emits `TurnFinished` — and with it the clear of that field — before any tool call is dispatched, so the number was zero for the whole of every tool call on every turn, while the spinner beside it kept advancing and made the wrong figure look live. The rung now runs its own clock (`running_tool_since`), started when the call is proposed and stopped when the rung comes down (the next turn starting, a permission prompt replacing it, the agent finishing, or a focus switch).

- **When several tool calls run at once, the figure is the age of the call the row names.** `running <tool>…` names one tool — the most recently proposed one — so the name and the number are stamped together and replaced together, and the row can never show one call's name wearing another's duration. It is deliberately not the age of the oldest call in the batch: that is a real question, but not the one a row naming a single tool asks, and a plausible batch-wide number pinned to the wrong call is harder to distrust than an obvious zero. A consequence worth knowing rather than reporting: during a parallel batch the figure restarts whenever a later call is proposed, because the name restarts with it. Per-call history is unaffected — the transcript still keeps a row per call with its own timestamp.
