### Fixed

- **The TUI status bar no longer gets stuck reading "running · thinking… Ns" after a Ctrl-C abort.** `Event::TurnAbortedByUser` (and its budget-trip sibling `Event::TurnAborted`) ended the current turn exactly like `Event::TurnFinished` does, but never reset `activity`/the elapsed clock the way that event's own arm does — the status line stayed wedged at whatever working rung was up when the abort landed until the next turn's first event overwrote it, even though the harness was already idle and accepting the next prompt.
- **A bash tool call's output no longer renders twice.** Its live `Event::ToolProgress` notes (streamed `-> {line}` as the process ran) repeated verbatim once the call settled and its own output block (`stdout:`/`stderr:`) rendered below them — both showed the same lines. The progress notes now render only while a call has no settled output yet; once it does, only the settled, cap/Ctrl-O-aware output block shows.
- **Settled tool output no longer trails a standalone blank-line-plus-`-` separator.** Stacked one per tool call down a transcript of several calls, it read as a wall of orphan `-` lines with nothing either side of them; the next entry's own header line already marks the boundary, exactly as it does for every other transcript entry kind.
- **"(cache: reporting unknown for `<backend>`)" (and its "not reported"/"not supported" siblings) no longer repeats on every turn-end summary line.** That family of wordings is a standing fact about the backend's own wire dialect, not a per-turn observation, so printing it after every single reply spammed the same sentence down the whole transcript. It still shows once in the status line's `tokens` field (unchanged) and now also in `/context` (new, for the focused agent) — the fact is never lost, only no longer repeated on a surface that printed it every turn. A genuinely per-turn fact — the actual cache-hit percentage, once a backend does report one — still renders on the turn-end line as before.
- **The session-scoped shell-prefix grant's `[p]` proposal no longer offers a wildcard for an interpreter/launcher/wrapper command.** `python3 -m pytest -q` proposed `python3 -m`, which would authorize `python3 -m` running ANY module, not pytest specifically. A first fix special-cased specific shapes in a table; a follow-up review found the table itself had holes: `env -i FOO=1 python3 -m pytest` still proposed `env -i FOO=1` (matching any later command), `uv run --with pandas script.py`/`go run -race ./cmd/server` stopped ON the flag right after `run` (`uv run --with`, `go run -race`) instead of falling back, `python3 -u -m pytest` stopped on the interpreter flag before `-m` (`python3 -u`, the exact wildcard this item exists to close), and `sudo`/`time`/other wrapper heads were not recognized at all. `conway_core::permission_pattern::default_shell_prefix` now follows three invariants instead of a shape table: (1) a proposal never ends on a flag or a launcher's own selector (`-m`, `run`, `dlx`/`exec`) when a target follows — it extends past the selector to the real target, or not at all; (2) a WRAPPER head (`sudo`, `doas`, `env` with any flag of its own, `time`, `nice`, `nohup`, `timeout`, `stdbuf`, `xargs`, `command`, `exec`, `caffeinate`) always proposes the whole command; (3) any flag this function would otherwise have to guess the arity of (an interpreter flag before a selector, a flag right after a subcommand selector such as `cargo run --bin`, or a script-literal like `bash -c`/`node -e`) also falls back to the whole command rather than a fixed-width guess. Ordinary commands (`git diff`, `wc -l`) and a launcher whose second token already names the real target (`npx eslint`, `node script.js`, `cargo test`) are unchanged. The docs now also state precisely that a whole-command proposal is not "only this one invocation" — it still prefix-matches a later command that appends more.

### Added

- **`/help` now mentions `[tui.editor_mode]`'s opt-in vim prompt editing**, how to toggle it (`/settings` → display → editor mode), and points at `docs/interactive.md`'s vim section — previously undiscoverable from the overlay that exists specifically to answer "what can I even do here."
