### Added

- **`/conway.skills.propose`, and an automatic proposal for a one-shot run that looks like hard work** — board item `01M3DTT078W25MD2S4527R0WAV` (slice 2, building on slice 1's mechanical trigger, `01M3DTRY56PQ5BX8HTVE7V96K0`). `/conway.skills.propose` forks an ephemeral child asking it to write a `SKILL.md` for the procedure just used (or say none is warranted), then shows the result in a modal: `Enter` writes it to `.conway/skills/<name>/SKILL.md` (a diff against an existing skill of the same name, never a silent replace), `e` opens it in `$EDITOR` first, `Esc` discards — nothing is ever written unattended. A `conway -p` one-shot run gets the same proposal automatically once its root finishes, shown as a plain `y`/`N` prompt on stderr (only when stdin is a real terminal — never on a pipe). `[plugins.config."conway.skills"].write_approval` (`ask`, the default, or `never` — deliberately no `always`) gates both surfaces identically. The ephemeral fork is bounded (15 steps, a 180-second deadline) so a proposal never costs unrequested tokens. See `docs/plugins/skills.md`'s new "Self-authoring skills" section for exactly when the automatic trigger fires (never inside the interactive TUI's own `keep_alive` session — only a one-shot run) and when it does not.
