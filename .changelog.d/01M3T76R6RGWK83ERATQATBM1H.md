### Fixed

- **conway no longer opens a session on `ollama_cloud/glm-5.2` or `glm-5.3` with a false warning that the model has no confirmed context window and will run against a 32,768-token floor** — board item `01M3T76R6RGWK83ERATQATBM1H`. The real admission bound for these models was never wrong (`conway_plugin_backends::model_metadata`'s bundled `DEFAULTS` table has declared their real `1,048,576`-token window since an earlier item, and every real turn already ran against it — confirmed by `crates/conway-plugin-backends/tests/glm_context_window.rs` and a new wire-level test in `tests/ollama_native_context_window.rs` asserting the exact `num_ctx` a real request sends). Only the PRE-FLIGHT notice printed before a session's first turn (`conway-cli`'s `resolve_first_turn_floor_notice`) was wrong: it decided "is this pair's window confirmed?" by checking only an operator-written `.conway/models.json` entry and the router's own capability index — both of which stay empty for a pair no one has explicitly added to `models.json`, even when conway's own bundled per-model table already has a real answer for it. The notice now also checks that bundled table (the same one `OpenAiCompatBackend::capabilities()` itself consults for real admission), so it can no longer contradict the number a turn actually runs against. A model this table genuinely has no opinion about (including a `model:tag`-suffixed variant of a bundled id, e.g. `glm-5.2:cloud`, which the bundled lookup's exact-then-normalized matching does not bridge to the bare `glm-5.2` entry) still prints the notice exactly as before.
