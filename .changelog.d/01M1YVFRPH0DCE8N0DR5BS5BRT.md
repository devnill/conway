### Added

- **Run a shell command yourself, right from the TUI prompt** — board item `01M1YVFRPH0DCE8N0DR5BS5BRT`. A line beginning with `!` runs the rest as a shell command (`$SHELL -c`, falling back to `/bin/bash -c`) in the session's cwd and shows its output and exit code in the transcript, in its own distinct styling — at **zero token cost**: the command and its output are recorded durably (a new, additive `LogRecord::OperatorShellRecord`, deliberately excluded from context assembly) but never sent to the model. `!> command` runs the SAME command but sends its output to the model as an ordinary message instead, so "run the tests and fix what fails" is one line. `!` alone runs nothing; `!!` re-runs the last `!`/`!>` command. `deny` rules targeting `bash` in `permissions.json` still refuse a `!` command, naming the rule, exactly as they would a model-issued `bash` call (`PermissionBroker::deny_rule_for_shell_command`, facade: `Conway::deny_rule_for_shell_command`); `prompt` rules, the current permission mode, and `pre_tool_use` hooks do not apply to `!` — the operator typing it already is the human those mechanisms exist to insert. `Ctrl-C` kills the command's whole process group (through `conway_tools::process::unix::kill_group`, never a second implementation) without touching the TUI; captured output is capped and says so when truncated. See `docs/interactive.md`'s new "Running a command yourself" section and `docs/permissions.md`'s "Confinement" section for the full operator-facing contract, including the disclosed limits (cwd is the session's spawn-time cwd, not a live `cd`-tracked one; `!` does not yet route through `conway.confine`'s confined shell).
