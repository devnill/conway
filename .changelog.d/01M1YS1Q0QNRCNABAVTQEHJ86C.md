### Fixed

- **A hosted model's real context window is no longer silently replaced by the 32,768-token dialect floor, and `conway routes explain` no longer prints `unknown` for a candidate's window** — board item `01M1YS1Q0QNRCNABAVTQEHJ86C`. Window resolution now has one implementation (`conway_plugin_backends::capabilities::max_context_tokens_source`, `conway_core::capabilities::ContextTokensSource`) with a new `Probed` layer: every OpenAI-compatible dialect's `/v1/models` endpoint is now consulted for a per-model `context_length`/`max_model_len` field, not only vLLM's own dialect, and setup-time discovery falls through to the same generic step for any dialect with no dialect-specific endpoint. `conway routes explain` prints each candidate's window with its provenance (`verified`, `models.json`, `probed`, or `floor (assumed)`), the model-facing runway notice names the provenance when a floor governs (e.g. "32.7k assumed -- set the real window in .conway/models.json"), and `Backend::context_window_source` carries the same resolved value into the router's capability index and the runtime's admission path, so all four surfaces read one resolved fact rather than four independent guesses.

### Added

- **`conway_core::ports::Backend::context_window_source`** — a provided trait method, mirroring `Backend::token_fidelity`, that answers "how much can this backend/model pair's declared context window be trusted" alongside the existing `Backend::capabilities`. `CapabilityIndex` now carries this provenance per `(backend, model)` pair alongside its existing `Capabilities`/`TokenCountFidelity` tables.
