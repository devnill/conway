### Fixed

- **The status line's `mode` field no longer reads `ready` for the entire duration of a running turn** — board item `01M32ECA6SAJBEKBPDC82DZSH7`. An automated pty watcher driving conway could not detect idle from the status line, because `mode` renders `Mode::Normal` as `ready` unconditionally — but `Mode::Normal` means only "no modal card owns the screen," which is true for an idle session AND for the entire span of an ordinary running turn (a turn opens no modal at all). `mode_label` now threads `AppState::activity` through `should_animate` — the identical predicate the `activity` field's own ladder already uses — so `Mode::Normal` renders `running` while a turn is actually working and `ready` only once it genuinely is; every other `Mode` variant (`awaiting permission`/`ask`/`intent`/...) already named its own modal and is unaffected, as are the `AUTO-ALLOW`/`plan` non-default-permission-mode labels this field also carries. See `crates/conway-cli/src/tui/view/status.rs`'s module doc and `docs/interactive.md`'s "The status line" section. The command-driven `conway.statusline` plugin (`crates/conway-plugin-statusline`) is a separate, shell-out-driven surface with no `Mode`/`activity` concept of its own and does not share this defect.
