### Changed

- **An agent definition's `max_steps`/`deadline_secs` frontmatter keys now actually govern a delegated child's budget — until this item, both parsed and round-tripped but were silently inert** — board item `01M32EC0F9S5HTZDR3DADFV9DK`. They sit as a new, lower-priority tier between the `subagent.max_steps`/`subagent.deadline_secs` plugin config keys and the hardwired 40-step/10-minute default: applied only when neither the call's own `budget` argument nor the matching config key already set a value (`resolve_budget`'s `max_steps_unset`/`deadline_unset`, in `crates/conway-tools/src/subagent/tools.rs`), and only to a `conway_fork`/`conway_spawn` child that names the def directly or inherits it via a fork (`SubagentHost::start`, `crates/conway-runtime/src/subagent.rs`). **Deliberately never applied to a root or resumed session, even one running under that exact def** — a root is watched by the human running it, who can read the transcript and interrupt, so a step or deadline ceiling picked by whichever def it happens to run under can only be wrong for that human. Anyone who already wrote a `max_steps`/`deadline_secs` into an agent def on the (previously correct) assumption that it was inert now gets a real ceiling on that def's delegated children. See `docs/agents.md`'s Budgets section for the full four-tier precedence.
