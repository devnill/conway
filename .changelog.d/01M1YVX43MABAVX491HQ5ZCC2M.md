### Added

- **`tui.theme` now accepts a preset name, not only a per-slot override table.** `"tui": {"theme": "dark"}` picks one of six built-ins -- `system` (the default, plain ANSI 16 colors, unchanged), `dark`, `light`, `solarized_dark`, `gruvbox`, `nord`. A new sibling key, `tui.theme_overrides`, overrides individual named styles on top of a preset, in the same shape `tui.theme`'s own object form already uses -- an existing `settings.json` carrying a `[tui.theme]` table keeps working unchanged. `CONWAY_TUI__THEME=dark` overrides it from the environment, the same `CONWAY_TUI__*` pattern every other `[tui]` setting already follows.
- **Custom themes as files.** A file at `<config dir>/themes/<name>.json` (same per-slot shape as `[tui.theme]`'s object form) is selectable by name through the same `tui.theme = "<name>"` key -- built-in names are tried first, then this file. An unresolvable name falls back to `system` with a non-fatal startup notice naming it.
- **`NO_COLOR` and `"tui": {"color": false}` render without color.** Either strips every named style's `fg`/`bg`, keeping modifiers that carry meaning on their own -- the selection highlight and the status line's reverse-video stay exactly as visible, and the permission mode's `AUTO-ALLOW` warning gains an underline so it still reads as distinct from `plan`'s own plain bold now that color can't carry that distinction.
- **`/settings` → "display" → `theme` cycles the active theme for the rest of the session.** Advances through all six built-in presets plus any custom theme file in `<config dir>/themes/`, wrapping -- session-only, like the other "display" rows, and the row names the currently active theme. Under `NO_COLOR`/`"tui": {"color": false}` the name still cycles but color stays off.

### Fixed

- **`NO_COLOR` is honored on presence alone, not only when non-empty.** [no-color.org](https://no-color.org) specifies that the mere presence of `NO_COLOR` disables color, regardless of its value -- `NO_COLOR=""` (set, but empty) was previously treated as color-enabled, contrary to the spec this feature cites. `Theme::resolve` now checks for the variable's presence, not its length.
- **A custom `tui.theme` name could escape `<config dir>/themes/` via path traversal.** `tui.theme` is settable from a project's (lower-trust) `settings.json`, and the theme name was joined onto the themes directory with no validation, so a name like `"../../x"` could resolve a JSON file outside that directory. A theme name must now be a plain file stem -- no path separators, no `..`, not absolute, not empty, no NUL byte -- and the resolved path's parent is verified to still be the themes directory; a name that fails either check degrades to the existing non-fatal "unknown theme" warning path, exactly like an unresolvable name already did.
