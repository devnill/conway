### Added

- **`Backend::cache_reporting` — a declared, per-backend capability stating whether a wire dialect has anywhere to report a cache hit at all**, distinct from `CacheMode` (support) and the existing per-response `CacheAccounting` (a discovered fact) — board item A5.7, "prompt caching reads zero on every real session". `AnthropicBackend` declares `Reported` unconditionally (the Messages API's `usage` object always carries both cache fields once present); `OpenAiCompatBackend` declares it from the resolved profile's new `reports_cache_usage` field, `true` only for the built-in `openai` and `kimi` profiles (both documented, verified fields) — every other built-in, including `ollama`, stays at the conservative `NotReported` default rather than a guess.
- **`conway routes explain` prints `cache: reported`/`cache: not reported`/`cache: unknown` per candidate**, and `--json` carries the same fact as `"cache_reporting"` — an operator can tell, before a single request is sent, whether a candidate's backend has anywhere to show a cache hit at all, or whether a `0%`/`not reported` figure they later see is because nothing was cached or because the wire format never carries that information.

### Fixed

- **The byte-stability precondition every prompt cache depends on is now proven directly**, for both the Anthropic and OpenAI-compatible wire dialects: rendering the same conversation twice with only the final user turn changed produces byte-identical `system`/`messages` content up to that turn, with a companion test proving the comparison actually catches front-of-conversation churn rather than passing vacuously. A new end-to-end wiremock test additionally proves the Anthropic path together, in one flow: a first turn places the cache breakpoint on a static prefix, and a second turn reusing that prefix — replayed against a response reporting `cache_read_input_tokens > 0` — both decodes into a nonzero `cache_read_tokens` and still carries the identical breakpoint.
