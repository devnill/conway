### Fixed

- **Two configured MCP plugins that happen to register the same tool name no longer crash the whole `conway` process** — board item `01M2PJM777FFSZW8GZWD46X49B`. `PluginRegistry::from_plugins` already built a correctly-named error (naming the colliding tool and both plugin ids); `conway-runtime`'s `Runtime::new` `.expect()`ed it away into a raw Rust panic instead of returning it. `Runtime::try_new` now propagates it, and `conway::ConwayBuilder::build` maps it to a `FacadeError::Build` — the identical shape and reporting path the neighbouring "duplicate plugin id" collision already uses — so an operator hitting either collision sees the same kind of named `conway: error: ...` line and a clean, non-panicking exit. `Runtime::new` itself is unchanged for every existing caller that still treats a malformed injected plugin set as a panic-worthy bug; conway does not auto-resolve the collision — you still have to rename or remove one of the colliding entries.
