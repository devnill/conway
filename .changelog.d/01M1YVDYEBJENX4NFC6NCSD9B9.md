### Added

- **`conway.web`: a first-party `web_fetch` (and optional `web_search`) tool — board item `01M1YVDYEBJENX4NFC6NCSD9B9`** — every comparable harness ships a built-in fetch tool; before this, a fresh conway install had no way to reach a URL at all (the model could only shell out to `curl`, and `bash` is off by default). `crates/conway-plugin-web` ships `web_fetch` (GET an `http(s)` URL, reduced to readable text — tags stripped, entities decoded — bounded to `max_bytes`, five redirects by default, each hop re-guarded) and `web_search` (behind an operator-configured provider — Brave is the one implemented this round). The SSRF/scheme guard fails closed: refuses any non-`http(s)` scheme, and refuses loopback/private (RFC 1918)/link-local (including the cloud-metadata endpoint `169.254.169.254`)/carrier-grade-NAT/broadcast/multicast/documentation-range targets, for both IPv4 and IPv6 (including an IPv4 address embedded in an IPv6 literal, and every decimal/octal/hex numeric IPv4 encoding the WHATWG URL Standard recognizes) — a domain name that resolves to any of those, or fails to resolve at all, is refused too. Disclosed, not covered: DNS-rebinding TOCTOU, 6to4/Teredo/NAT64 tunneled addresses — see `docs/plugins/web.md`'s own "what is and is not blocked" section for the precise, unhedged accounting. `web_search` is registered only when `[plugins.config."conway.web"].search` names a provider — a tool that would fail every call is never announced. Opt-in, deliberately not in the default opinion set (a materially different trust posture from every other first-party plugin: outbound network reach with the operator's own connectivity, from a fresh install) — see the crate's own module doc for the tier reasoning.
- **A structured `when: { domains: [...] }` permission-rule predicate**, alongside `paths_under`/`category_in` — `conway_core::permission_pattern::When::Domains` matches a URL-fetching tool's own rendering (the bare URL `web_fetch` renders as) against a configured host list, exact-host-or-subdomain, case-insensitive. Evaluated directly against `rendered` (no broker-side resolution needed, unlike `paths_under`), and fails closed in both directions: an allow rule never matches unparseable evidence; a deny/prompt rule always does. `{"select": {"tools": ["web_fetch"]}, "when": {"domains": ["docs.rs"]}, "then": "allow"}` allows that host (and subdomains) without a prompt; every other host still prompts. See `docs/permissions.md`'s new `domains` section.
- **`conway.web` is now actually installable.** `crates/conway-cli` links `conway-plugin-web` and resolves its published id through the same `[plugins].install` mechanism every other first-party plugin uses — `conway plugin install conway.web` (or `settings.json`'s `{"plugins": {"install": ["conway.web"]}}`) now reaches the real plugin, and `conway tools list`/the `/plugin` browser both show it. Still opt-in: absent from `first_party_plugins::DEFAULT_OPINION_SET`, so a fresh install does not gain outbound network reach unprompted.
