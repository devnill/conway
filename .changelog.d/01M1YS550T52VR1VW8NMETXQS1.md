### Added

- **`conway sessions list` shows a derived title for an unnamed session, instead of a blank `NAME` cell** — board item `01M1YS550T52VR1VW8NMETXQS1`. An unnamed session used to render as a bare 26-character id with nothing distinguishing one from another. `sessions list`'s `NAME` column (and `--json`'s new `title` field) now falls back to a title derived from the session's own first user turn — first line only, trimmed, bounded to a fixed length measured in CHARACTERS, never bytes, so a multi-byte character sitting at the boundary is never sliced mid-character. Deterministic and free: no model call, ever. Display-only and never persisted — the derived title is never written into the `conway.names` sidecar; `--json`'s `name` field is unchanged (still `null` for an unnamed session), and naming a session for real still goes exclusively through `sessions name`. See `docs/sessions.md`'s new "Where a title comes from" section.
- **Bare `/resume` (no argument) opens an interactive picker over the TUI's own project's sessions, instead of erroring** — board item `01M1YS550T52VR1VW8NMETXQS1`. Each row shows the session's name (or derived title), its first prompt, when it was last active, its record count, and any labels — reusing the same `Mode::UiForm` picker furniture `/model`'s own bare-argument menu already introduced, not a second list widget. `Up`/`Down` move the highlighted row; `Enter` resumes it through `apply_resume`, the exact same function a hand-typed `/resume <id>` already calls, so a session chosen from the picker reattaches through an identical path, never a second, independently-maintained mechanism; `Esc` cancels with nothing resumed. A project with no sessions yet gets a clear notice rather than an empty picker. `/resume <id|name>` is otherwise unchanged. Not yet built: a live filter box inside the open picker, and a key that widens the listing to sessions under a different project's own session-root key — both need a change to a file outside this change's own scope (`crates/conway-cli/src/tui/input.rs` for the first, `crates/conway/src/conway.rs` for the second); see `docs/interactive.md`'s new "`/resume` with no argument" section.

### Changed

- **The session project key now follows the enclosing git repository root, not the exact invocation directory** — board item `01M1YS550T52VR1VW8NMETXQS1`. Launching conway from a repository's root and from one of its subdirectories (with no `.conway/settings.json` of its own) used to key to two disjoint session stores — `docs/`'s history and the repository root's were invisible to each other, even though both discovered the identical config. The project key is now the enclosing git repository root when one exists (walking up from the invocation directory for a `.git` entry — a directory for an ordinary clone, a file for a linked worktree or submodule — the same rule `conway.idiom`'s own project-scope `instructions.md` discovery already uses, so the two never disagree about where a project starts), falling back to the exact invocation directory, unchanged, when it does not. Migrates nothing: an existing session directory under an old, subdirectory-derived key is left exactly where it is, untouched and still reachable exactly as before — only sessions created from here on share the repository-root key. See `docs/sessions.md`'s "Where session data lives on disk" and its new "If you already have subdirectory-keyed sessions" section.
