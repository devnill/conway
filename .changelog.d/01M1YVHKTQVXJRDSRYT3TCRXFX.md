### Added

- **Typing while the agent works is now visible and configurable** — board item `01M1YVHKTQVXJRDSRYT3TCRXFX`. Submitting a message while an agent's turn is running already reached the model eventually (a durable `UserTurn` that agent's own next context build picked up); now the input box's own border title and the transcript (a dim `queued>` entry) show it as pending until it is actually delivered. Every queued message is tagged with the agent it was typed for — switching focus (`/agents`, `/spawn`, `/fork`, `/model`, or any focus-nav key) before it is sent never redirects it to a different agent or strands it; a message queued for a non-focused agent shows only as a bare count on the strip, never its text. `Up` on an empty input recalls the most recently queued message belonging to the FOCUSED agent back into the editor (removing it from the queue, never also delivering it); with nothing queued for that agent, `Up` keeps its ordinary scroll meaning. To discard a queued message, recall it with `Up` and clear the input the ordinary way (`Ctrl-U`/backspacing) — `Esc` does not discard a queued message and keeps its existing meanings unconditionally (a reflex key is not a safe place for a destructive action). An agent that finishes outright before its queued messages can be sent never receives them; a notice lists what was not delivered, and the newest is restored to the input box if that same, now-finished agent is still focused with an empty input box. A new setting, `tui.busy_input` (`queue` default or `steer`), also reachable from `/settings`'s "display" group, picks what "submitted while busy" means: `queue` withholds until the agent it was typed for has genuinely gone idle — covering tool execution, not just model generation, so a queued message is never delivered mid-tool-call; `steer` delivers at the running turn's own next tool-loop step via the existing steer primitive (never mid-generation). Quitting (`/quit`/`Ctrl-D`) with a non-empty queue is refused once, with a notice, and confirmed by quitting again within a couple of seconds, mirroring double-`Ctrl-C`; the first `Ctrl-C` itself is not silent about a non-empty queue either — it leaves its own notice naming how many messages a second press would discard, without adding any extra press to the double-`Ctrl-C` exit itself. A `!`/`!>` shell command or a `/`-prefixed slash command is never affected by `busy_input`. See `docs/interactive.md`'s new "Typing while the agent works" section.

### Fixed

- **An agent's "busy" signal now covers tool execution, not just model generation** — board item `01M1YVHKTQVXJRDSRYT3TCRXFX`. `conway`'s `SessionHandle` gained `awaiting_prompt`, a new, honest "this agent is done with its whole turn, including any tools it dispatched, and is waiting for its next prompt" signal (`conway-runtime`'s existing `turn_in_progress` only ever covered the model round-trip and read `false` for the entire duration of every tool call). The TUI's queue delivery now keys off this signal instead of `turn_in_progress`, closing a gap where `tui.busy_input = queue`'s default behavior collapsed to `steer` timing on every tool-calling turn.
- **That same `awaiting_prompt` signal now also reads correctly for an agent that has never received its first prompt yet** — board item `01M1YVHKTQVXJRDSRYT3TCRXFX`. `Runtime::start_root` and the shared `Runtime::launch_agent` (used by `resume_root` and every fork/spawn child) now mirror the resume gate's own initial value onto `AgentTree` the instant the agent is attached, the same way every later transition already was. Previously the signal read "busy" for the entire window between an agent's construction and its first prompt/steer, even though the loop was genuinely idle at the resume gate that whole time.

### Changed

- **`busy_input = interrupt` and the `prompt.send_now` override were removed before release, by orchestrator ruling** — board item `01M1YVHKTQVXJRDSRYT3TCRXFX`. Both cancelled the focused agent (the same primitive `Ctrl-C` uses) before sending the new message; testing that path surfaced that this cancellation is unconditionally terminal for a kept-alive agent in every state, so neither could ever have delivered the new message into a continuing conversation — their only real effect was to end the operator's session. conway will not ship a `busy_input` mode or key whose effect is to end the session out from under the operator; `queue` and `steer` remain. A `settings.json` still naming `tui.busy_input = "interrupt"` (written against an earlier build of this item) loads successfully and falls back to `queue`, with a startup notice naming the fallback rather than silently changing the operator's configured mode. `F2` is unbound again.
