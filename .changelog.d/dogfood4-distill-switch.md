### Fixed

- **`/distill`'s `Enter` now actually switches the TUI onto the fresh agent it spawns** — a dogfood round 4 finding: the status bar kept the OLD session id and context total, `/context` reported the OLD agent's context, and the old transcript stayed on screen with the new agent's reply merely appended below it, because `App::spawn_from_distill` swapped the app loop's session handle but never reset `AppState` the way `/new` and `/resume` already did. `/distill`'s `Enter` now goes through that same shared reset, carrying the role/model pin forward exactly like `/new`.
- **The `/distill` cost notice no longer reads "0 tokens" for the new agent** — the brand-new agent's context total was read back before its first turn's context was actually assembled, landing on a zero-filled placeholder every time; the read now waits for a genuinely assembled report (or reports that it could not be read).
- **An "always allow" answered for this session no longer follows you into the next one.** `/new`, `/resume` and `/distill` cleared the TUI's list of session-scoped grants but left them active in the permission broker, so a command allowed "always" in one session ran unprompted in the next. All three now drop session-scoped grants when they switch sessions; grants from `permissions.json` and plugins are untouched.
