### Added

- **`conway.compaction`, an installable, off-by-default plugin that folds old tool results into one ephemeral summary segment** — packages `docs/plugins/cookbook.md` example 2's `CompactOldToolResultsHook`: every turn, every `ToolResult` segment beyond the most recent `fold_after_turns` (default 1, configurable via `[plugins.config.conway.compaction]`) folds in place into a short labeled placeholder, plus one aggregate notice segment carrying its own provenance naming `conway.compaction` and how many results it folded, so `/context` never shows an anonymous note where this plugin acted — and the TUI transcript shows the same notice live, the first time a request folds anything and again only when the fold count actually changes, so an operator who never opens `/context` still sees it happen. This is deliberately **the weakest form of what "compaction" usually means**: nothing persists the fold (recomputed from scratch on every single turn), no user/assistant text is ever summarized, and no model call is involved — see `docs/plugins/compaction.md` for the full caveat. Not in the default opinion set; an operator who wants it installs it explicitly.

### Fixed

- **`conway.compaction` orphaned every folded tool call, permanently breaking the session once folding started.** The shipped `CompactOldToolResults::before_request` deleted each folded `ToolResult` segment outright and spliced in one replacement summary segment, leaving every deleted result's own answering `ContentBlock::ToolUse` with no result at all. The runtime's own hook-coherence guard (`conway_runtime::context::hook_guard`) refuses, rather than repairs, a `ContextHook` output that orphans either half of a tool call/result pair — so the first turn that crossed `fold_after_turns` made every later turn in that session fail. Fixed by folding **in place**: a folded `ToolResult` segment keeps its own position, `call_id`, and `is_error`, with only its content replaced by a short `[folded by conway.compaction: ...]` excerpt of its own original text, so nothing is ever deleted and nothing can be orphaned. The aggregate `SystemNote` summary is still appended, now as one segment at the very end of the request rather than spliced into the middle, so `/context` and the TUI's live fold notice keep working unchanged.
