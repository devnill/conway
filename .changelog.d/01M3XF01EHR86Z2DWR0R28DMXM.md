### Fixed

- **A declarative hook or a subprocess plugin no longer gets killed on its first run just because a busy machine (a build running, Spotlight indexing a fresh build tree, `syspolicyd` scanning a newly written executable) made that one exec slower than usual** — board item `01M3XF01EHR86Z2DWR0R28DMXM`. A freshly-written script's first `execve` can pay a real, one-time OS-side cost (on macOS specifically, Gatekeeper/XProtect/Spotlight contention on a brand-new executable) that has nothing to do with the script itself being slow; a plugin that fails on its first run after install is a bad first impression. `HookEntry`/`SubprocessPluginEntry` gain a `first_call_timeout_ms` (default 20000ms, mirroring `McpPluginEntry`'s existing first-call tier) that `conway_tools::hook_runner::ProcessHookRunner` and `conway_plugin_subprocess` hand to whichever invocation of a given command is genuinely first — a hook runner tracks this per exact `command` (the OS cost is a property of the file being exec'd, not of which rule named it); a subprocess plugin's `tool.spec/1` discovery always qualifies, and so does its first ordinary one-shot `tool/1`/`capability/1` call. **Every invocation, first or not, additionally gets ONE bounded grace extension** if it runs past its deadline (waits the base deadline, then up to twice that again for the SAME still-running process before concluding it is genuinely unresponsive) — the identical mechanism `ChildSession` already gives MCP/persistent-subprocess sessions, extended here to the one-shot exec path both the hook runner and the subprocess plugin host use. A genuinely hung process is still killed and reported, naming the full bound it was actually given; the original request is never resent.
- **The persistent subprocess transport's own `first_call_timeout_ms` is no longer a structural no-op** — it used to pass `timeout_ms` to `ChildSession::spawn` twice, which this item's own investigation found while fixing the one-shot path; it now threads an operator-configured warm-up budget through, the same way `conway-plugin-mcp` already does.

### Changed

- **`docs/plugins/hooks.md`** (point 13) and **`docs/plugins/subprocess-plugins.md`** now document the `timeout_ms`/`first_call_timeout_ms` tiers, the bounded grace every call gets, and the macOS first-exec cost both exist to absorb.
