### Added

- **`conway.todo`, an opt-in task list the model writes and ticks off** — board item `01M1YVQ1F69PGMK8NW35FK2E62`. `todo_write` replaces the whole list (stable ids; omit one on a new item and it mints one) and `todo_read` reads it back; a `ContextHook` appends the current list as one compact segment near the end of a request whenever it is non-empty, without disturbing any earlier segment; a `todo` status-line contribution and `/conway.todo.list` surface it to the operator. State is kept per agent and persisted as a system-note log record on every `todo_write`, so it survives a `--resume`. Not installed by default — see `docs/plugins/todo.md`.

### Fixed

- **`conway.todo` no longer grows a request's context without bound** — same board item. Every `todo_write` persists its own system-note log record (for resume), and context assembly unconditionally replays EVERY past system note back as its own segment on every later request — so a long session with N `todo_write` calls used to carry N copies of the list (an increasingly stale one, past the first) into every request from the N-th call onward. `TodoContextHook::before_request` now removes every one of those persisted notes from the payload, on every request including the very first one built right after a note was written, before appending its own freshly rendered segment — one request therefore ever carries exactly one `conway.todo` segment, regardless of how many `todo_write` calls preceded it, and the removed notes were never part of what a backend could have cached in the first place. Also rejects a duplicate explicit `id` within one `todo_write` call, rather than silently picking a winner.
