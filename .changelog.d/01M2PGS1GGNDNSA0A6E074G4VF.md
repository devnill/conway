### Fixed

- **Every `/model`/`/role` switch no longer destroys its own confirmation notice before it is ever drawn** — board item `01M2PGS1GGNDNSA0A6E074G4VF`. `switch_session` (`tui/commands.rs`) built the switch's confirmation text and pushed it straight onto `state.transcript` before returning `Effect::FocusNewSession`, but that effect is handled in the very same synchronous tick by `app/focus.rs::try_focus_agent` → `AppState::focus_agent`, whose second line unconditionally clears `transcript` — wiping the notice before the run loop's single `if dirty { terminal.draw(..) }` check ever ran, on every switch. `switch_session` now parks the notice in a new `AppState::pending_focus_notice` field instead of pushing it directly, and `focus_agent` re-pushes it immediately after its own clear — after *every* clear, not just the first, since a single switch can drive more than one focus transition. `App::submit` is what ends the staged notice's life, deliberately not `Event::UserTurn`: focusing a child replays its history, so a replayed `UserTurn` would drop a notice staged by the very switch that just focused it. `try_focus_agent`'s failure path still surfaces the notice explicitly (no clear happens there), so a resubscribe failure does not silently drop a switch that already succeeded, and `focus_agent`'s own "a freshly-focused child shows only its own log" guarantee is unchanged for every other focus switch (bare `/fork`, `/spawn`, `/resume`), which never set the new field.
