### Fixed

- **Every `/model`/`/role` switch no longer destroys its own confirmation notice before it is ever drawn** — board item `01M2PGS1GGNDNSA0A6E074G4VF`. `switch_session` (`tui/commands.rs`) built the switch's confirmation text and pushed it straight onto `state.transcript` before returning `Effect::FocusNewSession`, but that effect is handled in the very same synchronous tick by `app/focus.rs::try_focus_agent` → `AppState::focus_agent`, whose second line unconditionally clears `transcript` — wiping the notice before the run loop's single `if dirty { terminal.draw(..) }` check ever ran, on every switch. `switch_session` now parks the notice in a new `AppState::pending_focus_notice` field instead of pushing it directly, and `try_focus_agent` takes it back out and re-pushes it immediately AFTER `focus_agent`'s clear (on both the success path and the failure path, so a resubscribe failure does not silently drop a switch that already succeeded) — `focus_agent`'s own "a freshly-focused child shows only its own log" guarantee is unchanged for every other focus switch (bare `/fork`, `/spawn`, `/resume`), which never set the new field.
