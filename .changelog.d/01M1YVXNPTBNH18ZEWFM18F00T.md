### Added

- **`conway doctor [--json]`** — board item `01M1YVXNPTBNH18ZEWFM18F00T`. Runs the checks a first-week operator would otherwise diagnose by hand, one error message at a time — does `settings.json` (and every layer above it) parse, is each configured backend reachable, does every routing chain's context window resolve with known provenance, does every installed plugin (including an MCP/subprocess plugin's own startup handshake) actually construct, are the binaries a configured feature needs on `PATH` (`git` for the plugin marketplace, the OS sandbox primitive for `conway.confine`), and where do sessions and board data for this directory resolve from — and reports each as `pass`/`warn`/`fail` with a one-line fix. Every check reuses the real feature's own code path (`ConwayBuilder::discover`/`from_config`, `backend_usability::classify_entry`, the `ConfigWarning`s `config::merge::validate` already computes, `agents::load_agent_defs`, the identical tiered plugin-install pipeline `sessions`/`routes` already run, `conway_plugin_confine::ConfinePlugin::new`) rather than a second, parallel probe that could drift from what a live session actually does. There is no `--fix`: every non-`pass` check names the edit or command that resolves it instead of performing one unasked. `conway doctor` is dispatched before config is even known to load successfully, so a malformed `settings.json` is itself reported as the one `fail` check (`config.loads`, carrying the real error) rather than refusing to run at all. Exits non-zero iff at least one check is `fail`; see `docs/scripting.md`'s new "`conway doctor`" section for the full check list and the `--json` schema.

### Fixed

- **`conway doctor` no longer creates a durable `conway.memory` store on disk** — same board item. Doctor reuses the real plugin-install pipeline on purpose, but that pipeline used to resolve `conway.memory`'s backing store for real whenever the plugin was installed (the common case — it is in the default opinion set), which meant `conway doctor` itself created `.conway/memory/memories` just by running, contradicting this command's own "no side effects" promise. It now hands that pipeline a fresh, non-durable, in-memory store instead, used only for the duration of the checks. Two smaller, related on-disk side effects in the same reused pipeline (a `conway.checkpoint` shadow-store directory and `.gitignore`, and the session store's own root directory) are documented in `doctor`'s own module doc as known, not-yet-closed follow-up work.
