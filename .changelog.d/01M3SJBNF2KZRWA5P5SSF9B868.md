### Changed

- **`conway.checkpoint.diff` no longer previews a forced restore as the plain command's own output.** For a path a plain `rollback <seq>` would REFUSE (a hand edit since conway's own last write), `diff` now says so first ("rollback will not touch this file ... `--all` would discard it and restore the content below"), and labels that path's own unified diff as what `--all` would produce, not what the plain command does.
- **A refused `conway.checkpoint.rollback` now fails rather than reporting success.** When any touched path hit a hand-edit conflict, the command returns an error instead of a plain report: headless (`conway conway.checkpoint.rollback ...`) this is a non-zero exit, and in the TUI it reads as an error notice — not an ordinary one — even when other paths in the same invocation restored cleanly. `--rewind` is never honored alongside a conflict either, since forking the conversation at a seq the files never fully reached would misstate what happened.
- **`conway.checkpoint`'s shadow store no longer lives inside the project.** It now resolves beside `conway`'s own session log, under the operator's config directory (`~/.conway/` or `$CONWAY_CONFIG_DIR`), keyed by the enclosing git root — never `.conway/checkpoints` inside the checkout. A snapshot no longer shows up in `git status`, and a launch from a project subdirectory shares the same store a launch from the repository root would (previously two disjoint stores, keyed to whichever directory `conway` happened to be launched from). An existing in-project store is migrated once, automatically (a plain rename); if that cannot complete (e.g. the two locations are on different filesystems), the old store is left in place and new snapshots start at the new location. A self-ignoring `.gitignore` is written into the store root as a backstop for the rare case (no operator home directory discoverable) where the store still resolves inside the project.
- **Docs reposition `conway.checkpoint` as a quick, transient undo, not a version-control substitute** — the operator's own ruling. `docs/plugins/checkpoint.md`'s "What this is for" and `docs/vision/CATALOGUE.md`'s reversal entry are updated accordingly; no merge or partial-restore capability is planned on top of it.
