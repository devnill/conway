### Added

- **`.changelog.d/` fragment files replace direct `CHANGELOG.md` edits for every user-facing change** — board item `01M1YY14QSB8WA6G1V5KT8NT0B`. Almost every board item is bound by `CONTRIBUTING.md`'s "docs and CHANGELOG in the same change" rule, and six to eight of them land concurrently, in isolated git worktrees, several waves deep — every entry going at the top of the same short `## [Unreleased]` subsection meant a batch landing was eight edits hand-merged onto the same three lines, pure conflict overhead with no useful signal when it went wrong. A writer now creates exactly one `.changelog.d/<slug>.md` fragment (`<slug>` derived from its work-item id or a short kebab-case name unique to that item), naming its target subsection(s) and carrying the same bullets that would otherwise have gone into `CHANGELOG.md` directly — two concurrent writers can never conflict, because each names a file nobody else names. `scripts/collect-changelog.py` folds every pending fragment into `## [Unreleased]`'s matching subsections (creating one that does not yet exist, or the whole section if `CHANGELOG.md` somehow has none) and deletes the fragments it consumed; `scripts/check-changelog-fragments.py` (wired into `scripts/check-fast-gates.sh`, not yet a CI job — stated plainly, the same way that script already discloses for `orphan docs` and `ideate record layout`) rejects a fragment naming an unknown subsection, an empty or headingless fragment, or a filename colliding with an entry already folded in. The subsection vocabulary (`Added`/`Changed`/`Fixed`/`Removed`) lives in one shared module, `scripts/changelog_fragments.py`, imported by both scripts rather than restated in either. See `.changelog.d/README.md` for the format and `CONTRIBUTING.md`'s "Docs and CHANGELOG in the same change" section for the rule this mechanism now serves.
