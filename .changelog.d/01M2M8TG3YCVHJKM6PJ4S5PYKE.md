### Fixed

- **An agent writing under a confined `conway.fs` root no longer gets a weaker durability guarantee than one writing unconfined** — board item `01M2M8TG3YCVHJKM6PJ4S5PYKE`. Board item `01M2M5KVC9J7MWY56DQK5YPXNR` added a parent-directory `fsync` after the atomic-write rename so a crash could no longer lose the rename itself, but that fix reached only the unconfined write path — the `cap_std`-based, TOCTOU-safe confined path (used whenever an agent's `conway.fs` root is set) never got it. `write_file_atomic_confined` now performs the identical post-rename parent-directory sync, expressed through `cap_std::fs::Dir` rather than a bare `std::fs::File::open`, so the two paths' durability guarantees are equal again. The confined path stays its own implementation (not merged into the unconfined one) — it exists specifically for the open-relative TOCTOU protection `cap_std::fs::Dir` provides, unrelated to this fix.
