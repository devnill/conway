### Added

- **`permissions.default_mode`: `settings.json` can now set which mode a new interactive session starts in** — board item `01M1YVP3FDPHY4WZ72SXMWAN2D`. Every TUI session used to start in `Prompt` unconditionally, with no way to say "always start me in plan mode" or "this project runs auto-allow" — the only way to change mode was `Shift-Tab`/`/settings` after the session had already begun. `permissions.default_mode` (`"prompt"` | `"plan"` | `"auto_allow"`, default `"prompt"`) answers that separately from the session's current, cycling mode; `/settings -> permissions` now shows both rows, distinctly labeled, so the two are never confused. A `--default-permission-mode` flag mirrors it for one TUI launch. **Fails closed on trust**: a PROJECT-scope `default_mode` (a cloned repository's own `.conway/settings.json`) has no effect until the operator runs `/trust permissions` for that project — the identical trust decision a project's `permissions.json` `allow` rules already require, reused rather than duplicated. User-scope `default_mode` (the operator's own file) applies immediately, on the same footing their own `permissions.json` already has. See `docs/permissions.md`'s "Setting the starting mode" section.

### Removed

- **`permissions.mode`/`permissions.allowed_tools`/`permissions.denied_tools` are no longer `settings.json` keys** — board item `01M1YVP3FDPHY4WZ72SXMWAN2D`. All three parsed successfully and did nothing for anyone running the real `conway` binary: they selected a fallback `PermissionGate` (`gates::from_config`) that only fires when `ConwayBuilder::build()` receives no gate of its own, and `conway-cli`'s `main.rs` always supplies one, on every dispatch target (TUI, one-shot, and every subcommand) — exactly the declaration-honesty failure this schema exists to prevent elsewhere. **This is a breaking change**: a `settings.json` still naming any of the three is now refused at load, with a message pointing at the actual replacement — `permissions.json` for allow/deny tool rules, `permissions.default_mode` for the mode a session starts in — rather than a bare "unknown field" error. Library embedders who relied on these keys to select the fallback gate now construct a `conway::gates::GateConfig` directly and pass it to the new `ConwayBuilder::with_gate_config`; `conway::presets::default_permissions_for_one_shot()` now returns that type instead of a `PermissionsConfig`. See `docs/migrating-from-claude-code.md`'s `permissions.defaultMode` row (moved from "Plugin" to "Maps") for the Claude-Code-compat angle.
