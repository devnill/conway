### Fixed

- **A delegated child burning through its budget is now visible to the operator** — board item `01M2RFDSTZPQF5VCNFCTSGQR92`. When a child agent crossed its 80% runway threshold, the resulting `Event::BudgetWarning` was emitted under the *child's* own freshly-minted session (`conway_spawn` creates one per child), and `EventStream::accept` dropped every cross-session event except `AgentSpawned`/`AgentFinished`/`AgentPromoted`. A TUI focused on the root is scoped to the root's session, so the warning never arrived: no transcript notice, and no `!budget` tag on the child's `/agents` row. Both surfaces were already written to handle it — `tui/state/agent_tree.rs` deliberately leaves a `Notice` "so an operator focused elsewhere still sees it", and `tui/view/agents.rs` tags the row off the same event — they were simply unreachable for a child. `BudgetWarning` now rides the same passthrough as the other cross-session lifecycle events. The parent-mailbox half (`AgentMessage::BudgetNotice` → a persisted `LogRecord::SystemNote`) is unchanged and remains the right shape for an orchestrating model reading it on its next turn; it was never a substitute for a live UI, because a child that dies before the parent takes another turn never surfaces through it at all.
