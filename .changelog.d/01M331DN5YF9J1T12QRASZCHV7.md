### Fixed

- **The `[p]` pattern editor's `Space` key no longer pins a field silently — the editor now states the resulting rule breadth before `Enter` commits it** — board item `01M331DN5YF9J1T12QRASZCHV7`, a live-reproduced finding: during a 2026-09-20 proxy run the operator pressed `Space` in the `[p]` field editor believing it would wildcard the `path` field, but `Space` is a wildcard/pin TOGGLE and every field starts wildcard — the keystroke silently PINNED `path`, turning an intended `read:*` grant into an exact-args rule on one file (`ARCHITECTURE.md`), and every later read re-prompted with no clue why. The editor already labeled each row `[pinned]`/`[wildcard]`, but nothing showed the CONSEQUENCE of those markers taken together. `draw_editing_pattern` now renders a live `grants: {…}` summary line — computed via the new `EditingPatternState::preview_rule` from the current field state through the same `Rule::describe` wording the durable-pattern offer's own `[p] grants: {}` footer line already uses (`any \`report\` call` vs. `report with path="ARCHITECTURE.md" pinned`) — plus a legend line stating plainly that `Space` toggles a field between wildcard and pinned. `submit_editing_pattern` now builds its rule via the same `preview_rule` the view reads, so the submitted grant can never drift from what was previewed. No change to what `Space` toggles, what fields start as, or what gets submitted — this is disclosure only. See `crates/conway-cli/src/tui/view/mod.rs`'s `draw_editing_pattern` doc and the render-level tests `editing_pattern_wildcard_state_discloses_any_call_and_the_toggle_legend`/`editing_pattern_pinned_state_discloses_the_exact_value_pinned`.
