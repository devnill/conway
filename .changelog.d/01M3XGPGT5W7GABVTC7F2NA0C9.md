### Fixed

- **`Ctrl-C` in the interactive TUI no longer ends your session.** Pressing it once — to stop a runaway reply, or with nothing running at all — used to terminate the root agent outright, even though the session looked idle; a second keystroke was never needed to lose the conversation. The first `Ctrl-C` now aborts only the current turn (killing any tool call it was mid-way through, process group and all) and the session accepts and answers your next prompt normally. Pressed with nothing running, it now genuinely does nothing destructive — a quiet notice says a second press is what quits — matching what `docs/interactive.md` always claimed. A second `Ctrl-C` within the existing window still force-exits, unchanged.
- **A cancelled tool call's process group was not reliably killed.** `ToolRunner`'s own cancellation race dropped a tool's in-flight call the instant a cancellation signal arrived, before a cooperative tool (like `bash`) ever got another chance to poll for it and run its own cleanup — so a backgrounded or long-running shell command cancelled mid-flight could outlive the cancellation that was supposed to stop it. The call is now always run as its own detached task, so dropping the loser of the race no longer also drops the tool's own in-progress cleanup.

### Added

- **`SessionHandle::abort_turn`**: a non-terminal turn cancellation. Unlike `cancel`/`cancel_with` (which always end the target), `abort_turn` stops only the target's current turn — the in-flight backend call and/or tool batch — and returns it to idling with its conversation intact. `conway_cancel` and `/cancel` keep their existing, unconditionally-terminal meaning; this is a separate primitive for an embedder that wants "stop this reply, keep talking."
- **`tui.busy_input = "interrupt"`** is back, built on `abort_turn`: submitting a message while the focused agent is busy now aborts its current turn and delivers your message into the same live agent once it reports idle — the "cancel this reply, keep talking" mode that was pulled from an earlier slice of this same feature for lack of a non-terminal cancel primitive.
- **`prompt.send_now`** (default `F2`): the per-message, one-off version of `interrupt` — abort-and-send a single message regardless of your configured `busy_input` mode.
