### Fixed

- **`--session <name>` on an unclaimed name now creates the session and binds the name in one step** — board item F10 (`01M250H60AHVSKFW12HX8G5FF9`). Previously `--session` accepted an operator-chosen name only if an earlier `conway sessions name` call had already bound it; an unclaimed name fell through to `session_names::resolve`'s generic "not a valid session id ... and no session is named that" refusal, so a script had to name a session before it could ever address it by that name. `oneshot::resolve_session`'s `--session` arm now mints a fresh session and binds the name to it in the same invocation whenever the argument is neither a valid session id nor an already-bound name — `conway --session daily -p "…"` twice now creates-then-binds on the first run and refuses with the documented "already exists, pass --resume instead" error on the second, exactly as it already did for a bare id. A bare id (valid or not) and an already-bound name are unaffected.
