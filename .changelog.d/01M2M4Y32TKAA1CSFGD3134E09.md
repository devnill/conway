### Fixed

- **`conway sessions`/`conway routes`, and `conway plugin install`/`conway plugin remove`, no longer refuse with the guided-setup provider error when no working model provider is configured** — board item `01M2M4Y32TKAA1CSFGD3134E09`. All four are pure, non-turn-proposing operations (session/route introspection; a single `settings.json` write) that used to still hit `main.rs`'s single provider-gate choke point ahead of every dispatch target, the residual `01M250BXW12HVMKZBCFPKG3704` left behind after widening `conway plugin list`/`conway tools list` the same way. In particular, `conway`'s own startup warning tells a fresh operator with no plugins installed to run `conway plugin install --defaults`; before this change, that exact command, against the exact fleet the warning fired for, refused with the provider error the warning was trying to route them around. `-p`, the TUI, and every other dispatch target that can reach a model are unaffected — the gate still fires for all of them, unchanged.

### Changed

- **`docs/sessions.md`, `docs/routing.md`, `docs/scripting.md`, `docs/tools.md`, `docs/plugins/README.md`** now describe `sessions`/`routes`/`plugin install`/`plugin remove` as needing no working provider, alongside the existing `plugin list`/`tools list` note.
