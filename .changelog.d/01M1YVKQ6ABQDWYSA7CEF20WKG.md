### Added

- **`/new`**: ends the current interactive session cleanly and starts a fresh root session in its place — same cwd, same role/model pin. Nothing is deleted: the old session stays exactly as it was, still listed by `conway sessions list` and still resumable with `/resume <id>`, and a notice names it the moment `/new` finishes. Refuses outright while a message is queued (`busy_input = queue`), a `!` shell command is still running, a `/distill` is still running, an `/ask` is still running, or a skill proposal is still running — naming what's in the way; a turn already in flight is aborted first (the same non-terminal abort `Ctrl-C`'s first press uses), not refused.
- **`/distill [<instructions>]`**: forks the focused agent (ephemeral, like `/ask`), runs one directed turn distilling a briefing for a fresh agent — the task, the decisions already made and why, the open questions, and the files that matter — bounded to 20 steps/180 seconds, and shows the briefing in a modal before anything else happens. `Enter` spawns a brand-new agent with the briefing as its opening prompt and switches the TUI onto it, reporting the old agent's context size versus the new one's; `e` edits the briefing in `$EDITOR` first; `Esc` discards it, spawning nothing. The old agent and its session are left untouched and forkable either way. Neither verb triggers automatically — both are typed, operator-initiated actions, the explicit, readable version of the fork-then-brief move `PHILOSOPHY.md` recommends for a conversation that has grown heavy. `Ctrl-C` abandons an in-flight `/distill` (a late reply, if one still arrives, is silently dropped) exactly the way it already abandons an in-flight `/ask`. A fork that produces no briefing (an error, a non-completed run, or no text at all) is reported as a notice and never offered as one.

### Fixed

- `/new` and `/resume` now keep the whole TUI configuration across their session reset, not just permissions: the active permission configuration (where a "remember this" grant gets written, the active/default permission mode, the permission file list, every configured deny/prompt rule), keybindings, input history, busy-input mode, the status line's field layout, the project-config-ignored security marker, and everything else set up once at startup from config/CLI/environment. Previously only a handful of process-lifetime fields survived the reset — the rest silently reverted to bare defaults, including persisting any NEW permission grant answered after either command for the rest of the process — no error, no notice. A session-scoped allow grant correctly does NOT carry forward either way: it belongs to the session that earned it.
- `/distill`: a `Ctrl-C` abandon immediately followed by a second `/distill` no longer drops the second one's briefing (nor opens the first, already-abandoned fork's late reply as though it were current) — each `/distill` fork now carries its own generation, and only the CURRENT one's reply is ever applied.
