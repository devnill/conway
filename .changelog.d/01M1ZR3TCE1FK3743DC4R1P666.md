### Added

- **`conway-plugin-mcp` now reads MCP's own `annotations.idempotentHint`, and retries a dying call for a tool that declares itself safe to** — board item `01M1ZR3TCE1FK3743DC4R1P666`. The auto-respawn machinery still never resends a request by default: a call whose session dies mid-flight fails closed while a fresh session is spawned for the next call. The one exception is a tool whose `tools/list` entry declared `idempotentHint: true` at discover time — that call's identical request is now resent, once, against the fresh session, through the same call site every other call uses. Absent, `null`, or explicit `false` all keep the unconditional fail-closed default, matching MCP's own documented posture that an unannotated tool is unsafe to retry. The annotation is the server's own, advisory, self-declared claim conway trusts but cannot verify — a server that lies about idempotency can cause a double execution.

### Changed

- **`docs/plugins/mcp.md`** now documents the `idempotentHint`-conditioned retry exception and states plainly that conway is trusting the server's self-declaration, not checking it.
